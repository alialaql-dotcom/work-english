# إنجليزي العمل — منصة تعلّم الإنجليزية لموظفي الإلكترونيات

موقع عربي (من اليمين لليسار) يعمل على الهاتف أولًا، لتعلّم الإنجليزية من الصفر حتى استهداف B1، مع تركيز على مواقف البيع في قسم الإلكترونيات.
لا يستخدم أي خدمة ذكاء اصطناعي مدفوعة؛ كل الدروس والتمارين والتصحيح تعمل داخل المتصفح.

> المحتوى تعليمي ومستقل، والمحادثات افتراضية. لا يمثل مكتبة جرير أو أسعارها أو سياساتها.

## القيود الحالية (بصراحة)

- **المنهج:** وحدتان من سبع مخطط لها. الوحدات القادمة (المواصفات، المقارنة، السعر والاعتراضات، التواصل مع الزملاء والمدير، نحو B1) ظاهرة في المسار على أنها «قريبًا».
- **B1:** الموقع لا يعلن بلوغ B1. سيُضاف اختبار شامل مع الوحدات الأخيرة. التحدث الحر ودقة النطق لا يمكن تقييمهما آليًا بدقة هنا.
- **النطق:** يستخدم صوت المتصفح. التعرّف على الكلام يعمل في Chrome وEdge وSafari الحديث، ولا يعمل في Firefox. في Chrome يُرسل الصوت لخدمة Google للتعرف عليه.
- **الإشعارات:** إشعار المتصفح يظهر فقط والموقع مفتوح. التذكير الموثوق مع إغلاق الموقع هو ملف التقويم (.ics). إشعارات Push الحقيقية تحتاج خادمًا ولم تُفعّل.
- **حذف الحساب نفسه:** المستخدم يحذف بياناته السحابية من الموقع؛ حذف الحساب (البريد) يتم من لوحة Supabase.

## النشر خطوة بخطوة (بدون برمجة)

ستحتاج 3 حسابات مجانية: **GitHub** و **Supabase** و **Vercel**. الوقت: حوالي 20 دقيقة.

### 1) قاعدة البيانات (Supabase)

1. ادخل [supabase.com](https://supabase.com) ← **New project**. اختر اسمًا وكلمة مرور، والمنطقة الأقرب (مثل Frankfurt أو Mumbai).
2. بعد الإنشاء: من القائمة اليسرى **SQL Editor** ← **New query**.
3. افتح الملف `supabase/migrations/0001_init.sql` من المشروع، انسخ كل محتواه، الصقه، ثم **Run**. يجب أن تظهر Success.
4. من **Project Settings ← API** انسخ:
   - **Project URL**
   - المفتاح **anon / public** (أو **publishable**)
   - ⚠️ لا تنسخ `service_role` أو `secret` أبدًا.

### 2) رفع المشروع (GitHub)

1. ادخل [github.com](https://github.com) ← **New repository** ← اسمه مثلًا `work-english` ← Create.
2. اضغط **uploading an existing file** واسحب كل ملفات المشروع (عدا مجلد `node_modules` إن وُجد) ← **Commit changes**.

### 3) النشر (Vercel)

1. ادخل [vercel.com](https://vercel.com) وسجّل بحساب GitHub ← **Add New ← Project** ← اختر المستودع.
2. قبل الضغط على Deploy افتح **Environment Variables** وأضف:
   - `VITE_SUPABASE_URL` = رابط المشروع من الخطوة 1
   - `VITE_SUPABASE_ANON_KEY` = المفتاح العام من الخطوة 1
3. **Deploy**. بعد دقيقة يعطيك رابطًا مثل `work-english.vercel.app`.

### 4) ربط الرابط بـ Supabase (مهم لرسائل التأكيد واستعادة كلمة المرور)

في Supabase: **Authentication ← URL Configuration**:
- **Site URL**: رابط موقعك من Vercel.
- **Redirect URLs**: أضف نفس الرابط.

### 5) جرّب

افتح الرابط من هاتفك ← أنشئ حسابًا ← أكّد بريدك ← أكمل درسًا ← افتح الرابط من الكمبيوتر وسجّل دخولك: يجب أن ترى نفس التقدم.
لتثبيته كتطبيق: في Chrome «إضافة إلى الشاشة الرئيسية»، وفي Safari «مشاركة ← إضافة إلى الشاشة الرئيسية».

### حدود الخطط المجانية (قد تتغير، راجع موقع كل خدمة)

- **Supabase المجاني:** المشروع يتوقف مؤقتًا بعد أسبوع تقريبًا بلا أي استخدام، ويُعاد تشغيله بضغطة من لوحة التحكم. وخدمة البريد المدمجة محدودة بعدد قليل من الرسائل في الساعة — مناسبة للتجربة، وللنشر العام اربط مزود بريد (SMTP) من **Authentication ← Emails**.
- **Vercel Hobby:** مجاني للاستخدام الشخصي غير التجاري.

## للمطوّر

```bash
npm install
cp .env.example .env.local   # اختياري: بدون القيمتين يعمل الموقع بحفظ محلي فقط
npm run dev                  # تشغيل محلي
npm test                     # كل الاختبارات
npm run build                # بناء للنشر في dist/
npm run build:preview        # ملف HTML واحد للمعاينة (حفظ محلي فقط)
```

### البنية

```
src/content/      المنهج: المفردات، الوحدات، اختبار المستوى (بيانات ثابتة)
src/lib/          المنطق النقي: تصحيح الإجابات، المراجعة المتباعدة، التقدم والدمج، توليد التمارين، الصوت، التذكير، المزامنة
src/state/        حالة التطبيق والمصادقة والمزامنة
src/components/   التمارين، البطاقات، الاستماع والتكرار
src/pages/        الصفحات
supabase/         مخطط قاعدة البيانات وسياسات RLS
```

### قرارات تقنية

- **محلي أولًا:** كل تقدم يُحفظ فورًا في المتصفح، ثم يُرفع للسحابة بعد ثوانٍ. الدمج بين الأجهزة تبادلي وآمن للتكرار: لكل درس/كلمة النسخة الأحدث، والأخطاء اتحاد، ونشاط كل يوم مسجل لكل جهاز على حدة حتى لا يتضاعف العد.
- **الأمان:** صف واحد لكل مستخدم في جدول `progress` مع RLS يمنع القراءة أو الكتابة لغير صاحبه، ويمنع الزوار تمامًا، ويرفض البيانات غير الصالحة. الموقع يرفض تلقائيًا أي مفتاح سري يوضع في الواجهة. عند تسجيل الخروج تُمسح النسخة المحلية، ولا يُدمج تقدم مستخدم سابق على نفس الجهاز في حساب جديد.
- **الإتقان:** الكلمة «متقنة» فقط بعد 3 نجاحات متتالية، في نوعين مختلفين من التمارين على الأقل، وبفاصل 7 أيام فأكثر. النجاح المتكرر خلال 6 ساعات لا يُحتسب تقدمًا في الجدول.
- **التوجيه بـ Hash** (`#/path`) حتى يعمل على أي استضافة ثابتة دون إعداد.

### الاختبارات

`npm test` يشغّل: سلامة المحتوى (كل الإجابات صالحة وكل المراجع موجودة)، تصحيح الإجابات، المراجعة المتباعدة وشروط الإتقان، الدمج والمزامنة بين جهازين، تحديد المستوى، التذكير، رفض المفاتيح السرية، **سياسات RLS الفعلية على Postgres حقيقي (PGlite)** بما فيها محاولات الوصول غير المصرح، وتدفقات الواجهة (تعارف ← درس كامل ← حفظ النتيجة ← قفل الدرس التالي عند الرسوب).
